# ONG Vida Plena

Aplicação **Nuxt 4 + Nuxt UI** para gestão de beneficiários e eventos da ONG Vida Plena, integrada ao **Supabase**.

O código da aplicação fica em `src/`. O `Dockerfile` na raiz é usado para publicar no EasyPanel.

---

## Pré-requisitos

- [Node.js](https://nodejs.org/) **20+** (recomendado LTS)
- npm (vem com o Node)
- Acesso ao projeto Supabase já configurado

---

## Rodar localmente

### 1. Entrar na pasta do app

```bash
cd src
```

### 2. Instalar dependências

```bash
npm install
```

### 3. Configurar variáveis de ambiente

Copie o exemplo e ajuste se necessário:

```bash
cp .env.example .env
```

Conteúdo esperado (`.env` ou `.env.local`):

```env
SUPABASE_URL=https://nbftaftsagbhzbypanyy.supabase.co
SUPABASE_KEY=sua_chave_publishable

# Também usadas pelo Nuxt em runtime (recomendado)
NUXT_PUBLIC_SUPABASE_URL=https://nbftaftsagbhzbypanyy.supabase.co
NUXT_PUBLIC_SUPABASE_KEY=sua_chave_publishable
```

> Use a chave **publishable** (ou anon) do Supabase — nunca a `service_role` no frontend.

### 4. Subir o servidor de desenvolvimento

```bash
npm run dev
```

Abra no navegador:

**http://localhost:3000**

Para expor na rede local:

```bash
npm run dev -- --host 0.0.0.0 --port 3000
```

## Banco de dados (Supabase)

O schema `public` deve conter as tabelas abaixo (já criadas no projeto).

### Relacionamento

```text
beneficiario (1) ──────< (N) eventos
```

- Um **evento** referencia **um** beneficiário (`eventos.beneficiario_id`).
- Um **beneficiário** pode estar vinculado a **vários** eventos (histórico).
- Ao excluir um beneficiário, os eventos vinculados são removidos (`ON DELETE CASCADE`).

### Tabela `beneficiario`

| Campo | Tipo | Obrigatório | Padrão | Descrição |
|-------|------|-------------|--------|-----------|
| `id` | `bigint` (identity) | sim | gerado | Chave primária |
| `created_at` | `timestamptz` | sim | `now()` | Data de criação |
| `nome` | `text` | sim | — | Nome completo |
| `indade` | `smallint` | não | — | Idade *(nome da coluna no banco)* |
| `contato` | `text` | não | — | Telefone, e-mail ou WhatsApp |
| `regiao` | `text` | não | — | Região / comunidade atendida |

```sql
create table public.beneficiario (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  nome text not null,
  indade smallint null,
  contato text null,
  regiao text null,
  constraint beneficiario_pkey primary key (id)
);
```

### Tabela `eventos`

| Campo | Tipo | Obrigatório | Padrão | Descrição |
|-------|------|-------------|--------|-----------|
| `id` | `bigint` (identity) | sim | gerado | Chave primária |
| `created_at` | `timestamptz` | sim | `now()` | Data de criação |
| `nome_evento` | `text` | não | — | Nome do evento |
| `descricao_evento` | `text` | não | — | Descrição / detalhes |
| `data_hora_inicio` | `timestamp` | não | — | Início do evento |
| `data_hora_fim` | `timestamp` | não | — | Fim do evento |
| `beneficiario_id` | `bigint` | não | — | FK → `beneficiario.id` |

```sql
create table public.eventos (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  nome_evento text null,
  descricao_evento text null,
  data_hora_inicio timestamp without time zone null,
  data_hora_fim timestamp without time zone null,
  beneficiario_id bigint null,
  constraint eventos_pkey primary key (id),
  constraint eventos_beneficiario_id_fkey
    foreign key (beneficiario_id)
    references public.beneficiario (id)
    on delete cascade
);
```

### Policies (acesso sem login)

As tabelas têm **RLS habilitado**. Para o app funcionar sem autenticação, é necessário permitir `SELECT`, `INSERT`, `UPDATE` e `DELETE` para as roles `anon` e `authenticated` (já aplicadas no projeto atual).
